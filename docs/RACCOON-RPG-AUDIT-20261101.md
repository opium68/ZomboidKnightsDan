## Project RPG: 이미 있는 기능과 추가 작업

### 처치 XP 제거는 설정으로 가능

`42/media/sandbox-options.txt`의 `RPGSkillTree.KillXP`는 최소 0이다.
`RPG_Server_XPEvents.lua`의 `rewardKills()`는 base XP가 0 이하면 즉시 반환한다.
직접 사망 이벤트와 MP 킬카운터 보정 경로가 이 함수로 모인다.
이 설정은 바닐라 스킬 XP를 끄는 설정이 아니다. 실제 MP 무기 모드 조합은 별도 확인한다.

### 레벨 +1 소모품이 이미 있음

`RPGSkillTree.LevelUpElixir`가 정의돼 있다.
`RPG_Server_GrowthElixirs.lua`의 `Server.use()`는 실제 소유 아이템 ID를 찾아 서버에서 소비하고,
`d.level += 1`, `d.skillPoints += 1`, 다음 레벨 필요 XP 갱신·상태 동기화를 수행한다.
최대 레벨에서는 소비 전에 거절하고, 재전송 시 이미 소비된 물품을 다시 사용할 수 없게 소유권을 확인한다.
따라서 **기존 효과를 성장 앰플의 이름·아이콘으로 표현하고 드롭 경로를 연결하는 방식**이 우선 후보다.
이는 설치·설정만으로 전체 원정 시스템이 완성된다는 의미는 아니다.

### 중요한 성장 보존 함정

레벨 소모품은 `xp`와 `totalXP`를 증가시키지 않는다.
기억의 돌 `SaveMemory()`는 RPG의 `xp`, `totalXP`와 바닐라 perk XP를 저장하고,
`RestoreMemory()`는 `totalXP`를 다시 지급해 레벨을 계산한다.
**앰플로 직접 올린 레벨·노드 투자·유전자 편집은 기억의 돌만으로 보존되지 않는다.**
또한 초기화 포인트 기본 지급은 totalXP 90000 단위다. 앰플 성장만 사용할 경우 기본적으로 쌓이지 않는다.
초기화 포인트 공급을 다크웹 상품·별도 보상으로 둘지 결정해야 한다.

### 라쿤시티 외부 우회 성장 경로

`RPG_Shared_JumpRewards.lua`의 기본 미니게임 보상에 XP 물약, 스킬 포인트 물약,
초기화 포인트 물약, 레벨 +1 물약이 들어 있다.
`RPG_Shared_JumpDrop.lua`는 전역 좀비 처치에 기본 5% 점프 상자 획득을 연결한다.
**KillXP=0만으로 '라쿤시티 앰플만으로 성장'이 완성되지 않는다.**
점프 상자·XP 물약 및 사용자 수정 보상표를 함께 제한해야 한다. 강화/일반 상자 드롭은 원하는 경제 정책에 맞춰 별도 결정한다.

중복 사망 이벤트·시체 접근·재시작으로 보상이 늘지 않도록 지급 이력을 둔다.

- `BasementPoliceCarSpawns.lua`는 전역 ModData `BasementPoliceCarSpawns`에 좌표별 생성 기록을 저장한다.
  재시작 시 구역을 원상 복구하려면 해당 도시 좌표 기록과 차량 DB까지 함께 설계한다. 월드 전체 ModData를 지우면 안 된다.
- 경찰서 배지 퍼즐은 별도 좀비 생성 명령이 있다. 회차 중 증원 없음 정책과 맞출지 명시적으로 결정한다.
- 원본 `RaccoonCityServerCommand.lua`는 좀비 생성·스프라이트 추가 요청의 좌표·수량을 클라이언트 인자로 받으며, 이 핸들러 안에서 거리·퍼즐 단계 검사가 보이지 않는다.
  원정용으로 사용하려면 서버 판정과 제한을 추가하는 편이 적절하다. 실제 악용 재현은 하지 않았다.
- PZLinux 원정 키·팀 권한·강제 마감·오프라인 귀환 판정은 내려받은 맵/RPG/복원 모드에 포함된 기능이 아니다.
- 전체 도시 온라인 즉시 초기화는 검증하지 않았다. 정상 종료 후 구역 저장 파일·퍼즐·차량 기록을 함께 처리하는 방식을 먼저 격리 검증한다.

## 검증 수준과 다음 구현 순서

완료: 공식 원본 분리 다운로드, 757개 파일 해시 대조, Lua·설정 정적 분석, 12셀 방 데이터·lotpack 파싱, 자체 보관함 후보 87곳 추출.
미완료: 모드 통합 부팅, 실제 맵 동선·시야·퍼즐, 컨테이너 엔진 생성·접근, 백신 좀비 분포, 앰플 소비·복원·초기화의 실제 MP 테스트.
현재 결과는 **구현 가능 경로와 파밍 후보를 찾은 분석**이며 운영 사용 보증이 아니다.

권장 순서: (1) 지도 답사/컨테이너 식별 확인 → (2) KillXP=0와 기존 +1 소모품 검증 →
(3) 계정 성장 보존 → (4) 회차별 보상함 선정·백신 좀비 드롭 → (5) PZLinux 키·철수·마감 → (6) 내부 생존자가 없는 정상 재시작의 구역 초기화.

## 후속 검토: 원본 전리품 유지 기준

사용자는 원본 전리품을 그대로 두는 방향에 동의했다. **일반 전리품·고유 보상 제거는 현재 확정 패치가 아니다.**
원본 보상과 퍼즐을 우선 유지하고, 실제 수급을 측정해 후속 조정하는 것을 검토 기준으로 한다.
아래는 추가 정적 검토 결과와 제안이며, 운영 적용하거나 새 규칙을 확정한 것이 아니다.

| 항목 | 코드/현재 설정에서 확인 | 권고 또는 미결정 사항 |
|---|---|---|
| 전역 위험도 | `WorldDangerEnabled` 기본 true. 서버는 월드 나이에 따라 로딩된 좀비의 체력·속도를 처리 | 원정 외 지역의 기존 난이도를 유지하려면 false로 시작. 이미 오래된 월드라면 첫 도입부터 높은 단계가 적용될 가능성 확인 |
| 자동 습격 | `HordeRaidChancePercent` 기본 0.2, 규모 300. `RPG_Server_HordeRaid.lua`의 킬 이벤트는 XP 함수와 독립 | 회차 중 증원 없음 정책에 맞춰 습격 확률 0 권고. KillXP=0만으로 꺼지지 않음 |
| 소환 두루마리 | `RitualScrollDropPercent` 기본 0.5. 실제 사용 핸들러가 플레이어 위치에 좀비 소환을 예약 | 드롭 0과 별개로 보상 상자·구매 등 획득 경로 및 사용 핸들러도 점검. 라쿤시티와 원정 대기 구역에서는 사용 차단 권고 |
| 차원 보관함 | `RPG_Server_DimensionalVault.lua`의 dispatch/handle는 사망·요청·소유권·용량 등을 검사하지만 원정 지역/참가 상태는 검사하지 않음 | 원정 중 서버에서 보관·꺼내기 명령 차단 권고. UI만 숨기지 않음. 사망 후 보관함 내용까지 이어줄지는 캐릭터 성장과 별도 결정 |
| 앰플 현장 사용 | 기존 레벨 물약 핸들러는 사망·소유권·최대레벨을 검사하지만 원정 상태는 검사하지 않음 | 원정 중 즉시 사용+사망 후 성장 보존이면 '먹고 사망'으로 성장이 확정됨. 탈출이 목표라면 귀환 후 사용 권고. 사용자 미확정 |
| 성장 재화 우회 | 점프 상자 기본 보상이 XP·레벨·SP 물약을 지급 | 원본 라쿤시티 전리품 유지와는 별개로 RPG 미니게임 성장 보상만 제한. 기존 사용자 보상 설정도 검사 |
| 초기화 포인트 | 직접 +1레벨 소모품은 totalXP를 늘리지 않으며 기본 reset point는 totalXP 기반 | 스킬 재분배 수단이 없어지지 않게 초기화 물약을 다크웹에서 공급하거나 별도 규칙 마련 |
| 캐릭터 성장 복원 | RPG 자료는 `player:getModData().RPGSkillTree`. 레벨·남은 SP·사용 SP·노드·유전자 편집이 서로 연관 | 서버 계정별 허용 필드 목록으로 함께 저장·검증·복원. 스탯만 더하거나 레벨만 복원하지 않음. 재접속 중복 적용·새 캐릭터 초기 보너스 중첩 검사 |
| 백신 좀비 | SpiffoKnew는 전역 기본 좀비 의상 테이블에 추가됨 | 도시에서 확보 가능한 개체 수와 실제 지역 의상 테이블을 먼저 확인. 무작정 전역 출현율을 올리지 않고 도시에서 생성한 개체 표식으로 추가 앰플 판정 |
| 카드 경제 | 현재 PZLinux 자동 해킹은 카드 전량을 소비하고 카드당 `100~200 × (전기 스킬+1)` 금액 계산 | 카드 출현율만으로 예산을 잡지 않음. 숙련자 수입과 키·장비 가격·재고를 함께 비교 |
| 상점 선택지/재고 | 현재 자체 Market은 상품군별 0~3종, 별도 탄약·탄창·차량 규칙을 사용 | 선택지 확대와 재고 확대를 구분. 원정 키는 일반 장비군 추첨에서 독립시키는 안 검토 |
| 원정 키/시계 | 키 입장 기능은 신규 작업. 운영 추적 INI는 `PauseEmpty=true` | 주기는 게임 시계 기준으로 저장. 키 구매/사용 전에 남은 시간 표시. 늦게 입장해도 종료가 연장되지 않음. 최소 잔여 시간·키 소비·팀 인원은 미확정 |
| 공유 도시 | 현재 설계는 서버당 하나의 도시·공통 회차 | 앞선 팀이 전리품을 가져간 상태를 후발 팀에게 알려야 함. 키를 쓰면 새 보상이 생성되는 것으로 오해하지 않게 한다. 개인별 던전은 별도 기능 |
| 재입장/로그아웃 | 원정별 참가 명단을 별도로 만들 필요 | 키가 팀 1회 입장인지, 해당 회차 재입장 권한인지 결정. 내부 로그아웃·도시 밖에서 종료된 회차의 재접속·사망 시 부활 위치를 함께 처리 |
| 마감과 맵 리셋 | 청크 리셋 외에도 퍼즐/GameTime 데이터·차량 DB/생성 기록 존재 | 마감은 입장 차단·미귀환 판정으로 처리하고, 물리 초기화 완료 전 재개방하지 않음. 운영 중 파일 삭제로 즉시 도시를 재생성하는 방식은 채택하지 않음 |
| 도시 점거 | 플레이어가 바리케이드·은신처·차량으로 접근을 바꿀 수 있음 | 도시 내부 거점/건축/차량 반입·회수 범위를 결정. 외부 일반 거점과 원정 리셋 범위 분리 |
| 기존 수리 모드 | 강화는 무기 최대내구도·피해 등과 modData를 변경. 영혼 수리의 근접 경로는 기존 물품을 제거하고 같은 타입 새 물품을 생성해 강화레벨을 복원 | 기존 수리킷·무기 수리·연마·부착물·사용자 개조 자료와 조합 테스트. 현재 코드에서 기존 modData 전체를 이관하는 경로는 보이지 않아 추가 정보 손실 가능성 있음. 실제 손실 재현 전 |
| 원본 고유품+RPG 강화 | 원본 특수 무기 성능과 RPG 패시브/강화가 함께 적용될 수 있음 | 전리품은 유지하고 대표 무기·갑옷·NV·공격속도 조합부터 시험. 밸런스와 실제 동기화 확인 후 수치 결정 |

설계상 우선 결정할 3가지: **원정 중 앰플 사용 여부 / 원정 중 차원 보관함 허용 여부 / 도시 전체 초기화에 필요한 정상 종료 운영 방식**.
수치 조정보다 이 규칙을 먼저 정해야 사망·철수·보상 보존의 의미가 일관된다.
