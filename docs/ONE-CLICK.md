# 원클릭 실행 안내

## 호스트

프로젝트 루트의 `HOST-SETUP-AND-RUN.cmd`를 더블클릭한다. UAC 창에서 관리자 권한을 허용하면 다음 작업을 순서대로 처리한다.

1. 실행 중인 서버와 포트 충돌 확인
2. SteamCMD가 없으면 공식 배포본 설치
3. 전용 서버가 없으면 App 380870 설치
4. 관리자·고정 서버 접속 암호 파일 확인
5. 설정·manifest 검증
6. 설정된 DuckDNS 주소 즉시 갱신 후 서버 실행 중 5분 간격 갱신
7. Windows 방화벽 UDP 16261/16262 규칙을 모든 네트워크 프로필에 확인 또는 생성
8. 현재 설정·DB·세이브 자동 백업. 설치된 7-Zip의 빠른 압축을 우선 사용해 로컬 임시 폴더에서 ZIP을 완성·검증한 뒤 `backups`로 이동하며, 7-Zip이 없으면 PowerShell 빠른 압축으로 대체. 서버 자체의 시작 시 백업(`BackupsOnStart`)은 꺼서 중복 백업을 피하며, 게임 버전 변경 시 백업은 유지
9. 추적 설정과 서버 전용 로컬 모드 배포
10. 서버 실행과 Workshop 동기화
11. `quit` 종료 후 로그 자동 판정

일반 실행은 설치된 서버 버전을 유지한다. 게임 업데이트를 적용할 때만 `HOST-UPDATE-AND-RUN.cmd`를 사용하며, 이 경로는 업데이트 전에 자동 백업하고 같은 실행의 설정 배포에서는 그 백업을 재사용한다. 일반 실행·최초 설치에서는 설정 배포 전에 한 번 백업한다. `deploy-config.ps1`을 단독 실행할 때도 기본 백업은 유지된다.

서버가 켜진 동안 이 창을 닫지 않는다. 종료할 때는 서버 콘솔에 `quit`을 입력한다. 현재 호스트는 공인 IPv4를 PC가 직접 받는 모뎀 직결 상태라 라우터 포트 포워딩이 필요 없다. 인터넷에 직접 노출되는 만큼 방화벽의 다른 규칙은 임의로 완화하지 않는다.

## 월드 백업 복원

서버를 `quit`으로 정상 종료한 뒤 `scripts/restore-world-backup.ps1`에 복원할 ZIP의 `-Archive`와 미리 확인한 `-ExpectedSHA256`을 지정한다. `-ValidateOnly`는 파일 교체 없이 백업 구조와 해시를 검사한다. 실제 복원은 ZIP을 별도 폴더에 추출·검증하고 현재 월드 전체를 `Zomboid/backups/rollback/before-*`에 보관한 뒤 교체한다. 모드·서버 설정·접속 계정 DB는 교체하지 않는다. `-PreservePlayers`를 지정하면 현재 `players.db`와 그 저널 파일, ID 할당 데이터를 유지한다. 지정하지 않으면 캐릭터도 백업 시점으로 돌아간다. 복원 후 게임을 완전히 종료했다가 재접속한다. 기존 세이브 재현용 회복이므로 월드 초기화의 ResetID 변경 절차를 같이 실행하지 않는다.

## 월드 초기화

서버 콘솔에서 `quit`으로 정상 종료한 뒤 프로젝트 루트의 `RESET-WORLD.cmd`를 실행한다. 화면에 표시되는 서버 이름을 그대로 입력하면 설정·계정 DB·현재 월드를 날짜별 ZIP으로 먼저 백업하고, `escape_test` 월드 저장 폴더와 그 안의 캐릭터만 초기화한다. 설정, 모드, 외부 접속 계정 DB, DDNS 및 비밀번호는 유지되며, `ResetID`는 자동으로 변경되어 플레이어의 이전 월드 캐시와 새 월드가 섞이지 않는다. 완료 후 `HOST-SETUP-AND-RUN.cmd`를 실행하면 새 월드가 생성된다.

## DuckDNS 최초 설정

1. DuckDNS에 로그인해 원하는 서브도메인을 하나 만든다. 서브도메인은 서버 비밀번호와 전혀 다른 문자열로 정한다.
2. 프로젝트 루트의 `CONFIGURE-DUCKDNS.cmd`를 실행한다.
3. 만든 서브도메인과 DuckDNS 화면의 token을 입력한다. token은 입력 중 표시되지 않으며 무시되는 `config/secrets.psd1`에만 저장된다.
4. 스크립트가 실제 갱신 성공을 확인하고 해당 도메인이 들어간 친구용 ZIP까지 다시 만든다.

서브도메인은 공개 DNS 정보이므로 비밀번호를 서브도메인으로 재사용하면 안 된다. 실수로 같게 등록했다면 서버를 켜지 말고 먼저 `SET-SERVER-PASSWORD.cmd`로 서버 비밀번호를 새 값으로 변경한다. 그다음 DuckDNS 화면에서 기존 서브도메인을 삭제하고 다른 이름을 만든 뒤 `CONFIGURE-DUCKDNS.cmd`를 다시 실행한다. 같은 값이 남아 있는 동안 호스트 원클릭 실행도 보안 오류로 중단된다.

이후에는 호스트 원클릭 런처가 시작 시 한 번, 서버가 켜진 동안 5분마다 주소를 갱신한다. 일시적인 DuckDNS 장애가 나면 마지막 DNS 레코드로 서버 실행은 계속된다.

## 플레이어 배포 패키지 만들기

호스트가 `MAKE-PLAYER-PACKAGE.cmd`를 더블클릭하면 설정된 DuckDNS 도메인을 우선 사용해 `packages` 폴더에 암호 없는 ZIP을 만든다. DuckDNS가 아직 없을 때만 직결 공인 IPv4를 자동 감지하거나 주소를 묻는다. ZIP에는 주소·포트·공개 Mod/Workshop ID와 서버 전용 `KnoxEscapeQuest` 모드가 들어가며 비밀번호, token, Project Zomboid 게임 본체는 들어가지 않는다. 이 ZIP을 친구에게 전달하고, `COPY-SERVER-PASSWORD.cmd`로 복사한 고정 서버 암호는 별도로 보낸다. DuckDNS를 사용하면 통신사 IP가 바뀌어도 주소 때문에 패키지를 다시 만들 필요가 없다. 탈출 모드나 런처가 갱신되면 새 ZIP을 다시 배포한다.

플레이어는 Steam에서 Project Zomboid를 최신 Stable 42.21.0으로 업데이트하고, 압축을 푼 뒤 `OPEN-MANUAL.cmd`를 더블클릭해 비개발자용 오프라인 안내서를 먼저 읽는다. `JOIN-SERVER.cmd`를 실행하면 먼저 동봉된 탈출 모드를 `%USERPROFILE%\Zomboid\mods\KnoxEscapeQuest`에 자동 설치·갱신한다. 다른 버전이 있으면 삭제하지 않고 `%LOCALAPPDATA%\PzEscapeLauncher\local-mod-backups`로 옮긴다. 그다음 패키지의 서버 Mod ID와 `Zomboid\mods\default.txt`의 전역 활성 모드를 대조한다. 서버에 없는 모드가 발견되면 다음 중 하나를 직접 선택한다.

- `Y`: 기존 `default.txt`를 날짜별로 백업하고 전역 활성 모드를 모두 비운 뒤 접속한다. 서버 모드는 접속 과정에서 서버 목록대로 로드된다.
- `N`: 파일을 바꾸지 않고 접속한다. 클라이언트 전용 모드가 있으면 체크섬 오류가 계속될 수 있다.

선택 결과와 서버 모드 목록의 지문을 로컬 AppData에 기록하므로 같은 목록에는 다시 묻지 않는다. 서버 모드 구성이 바뀌면 자동으로 다시 검사한다. 수동 재검사는 `CHECK-CLIENT-MODS.cmd`, 정리 전 목록 복구는 `RESTORE-CLIENT-MODS.cmd`를 사용한다. 패키지에 주소가 들어 있으므로 이후 Steam과 Project Zomboid가 해당 서버의 접속 흐름으로 열린다. 주소가 바뀌면 `RESET-SERVER-ADDRESS.cmd`를 실행한다.

## 보안상 남는 한 단계

Project Zomboid의 `+connect`는 주소와 포트는 받을 수 있지만 비공개 서버의 계정/암호를 안전하게 명령줄로 넘기는 공식 방식을 제공하지 않는다. 따라서 최초 계정 선택·암호 입력은 게임 화면에서 해야 한다. 암호를 배치 파일·URI·프로세스 인자에 평문으로 넣지 않는다.

현재 서버는 `Open=true`, `Public=false`, `MaxAccountsPerUser=1`이다. 친구는 서버 주소와 고정 공용 서버 암호를 받은 뒤 자신의 계정 이름·계정 암호를 최초 접속 화면에서 직접 만든다. 호스트가 `adduser`를 실행할 필요는 없고 공개 서버 목록에도 노출되지 않는다. 주소나 도메인은 포트 검색으로 발견될 수 있으므로 비밀번호를 계속 사용한다. 암호가 유출되면 서버를 멈추고 `SET-SERVER-PASSWORD.cmd`로 바꾼 뒤 호스트 런처로 재배포한다.

## 문제 해결

- `Workshop ID absent from manifest: 3403870858`: Lifestyle 추가 시 `mod-manifest.csv` 항목이 누락된 문제다. 2026-10-09 명세에 Workshop ID와 LifestyleHobbies를 등록해 수정했다. 모드 명세·설정을 함께 갱신하며, 릴리스 빌드도 시작 전 명세 검증을 수행한다. 이 수정은 클라이언트 패치나 ZIP 재배포가 필요하지 않다.
- 창이 곧바로 닫힘: 프로젝트 폴더를 OneDrive 온라인 전용이 아니라 로컬 사용 가능 상태로 만든다.
- 관리자 권한 거부: 방화벽 자동 설정은 건너뛰지 말고 UAC를 승인하거나 관리자에게 요청한다.
- UDP 16261 사용 중: 기존 서버 창에서 `quit` 후 다시 실행한다.
- Steam URL 프로토콜 없음: Steam 클라이언트를 설치하거나 복구한다.
- 서버 응답 없음: 서버의 `SERVER STARTED`, 방화벽, 라우터 포워딩, CGNAT 여부를 차례로 확인한다.
- DuckDNS 갱신 실패: DuckDNS에서 서브도메인이 실제 생성됐는지 확인하고 `CONFIGURE-DUCKDNS.cmd`를 다시 실행한다.
- ZIP 사용 중 오류: 탐색기 미리보기나 압축 프로그램이 기존 ZIP을 잡고 있어도 이제 날짜가 붙은 새 ZIP으로 자동 우회한다.
- 모드 버전 불일치: Steam과 게임을 완전히 종료하고 Workshop 다운로드를 갱신한다.
- 클라이언트 전용 모드 체크섬 오류: `CHECK-CLIENT-MODS.cmd`를 실행해 다시 대조하고 정리를 선택한다.

## 2026-11-06 초기화 및 백업 보완

정상 종료 확인 파일이 없어도 이제 기존 월드로 시작하며 라쿤시티 초기화만 보류한다. 확인 파일을 수동으로 만들지 않는다. 초기화 진행 중 표식이나 DB 오류는 별도로 확인해야 한다. 시작 전 백업은 검증된 이전 ZIP에서 변경 파일만 갱신해 새 독립형 전체 ZIP을 만든다. 사용 중인 서버는 정상 종료한 뒤 기존 호스트 실행기를 사용한다. [상세 검증 기록](SERVER-START-BACKUP-20261106.md).
