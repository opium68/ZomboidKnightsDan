# 패치 예정 목록

2026-10-18 기준. 아래 구현 항목은 `0.1.0-20261018.4`로 운영 반영했다. 실제 멀티플레이 확인과 험비 조사는 별도 대기다. [패치·검증 기록](KNIGHTS-SUPPLY-20261018.md).

## 구현·운영 반영 완료

- [x] **퀘스트·계약 생성 좀비의 플레이어 추적**
  - 방어·탈출 퀘스트 웨이브 등 전투 임무로 생성된 좀비가 시야에 플레이어가 없어도 대상의 현재 위치를 주기적으로 갱신해 추적하도록 한다. 각 생성 경로를 확인하고 임무 식별 표식을 연결한다. 사냥 표적은 제외하며 기존의 이동 불가·지정 위치 대기 방식을 유지한다.
  - 기존 건물 보호 계약의 추적 방식을 확장한다. 계약 좀비는 살아 있고 접속 중인 해당 계약 참여자 중 가까운 사람을 추적하고, 탈출 퀘스트 웨이브는 해당 단계의 유효 참여자를 대상으로 한다.
  - 대상이 사망·접속 종료하면 다른 유효 참여자로 전환하며, 대상이 없거나 임무가 완료·취소되면 강제 추적을 해제한다. 임무 처치 수 달성만으로 완료되지 않는 계약은 실제 완료/취소까지 유지한다.
  - 사냥 표적의 이동 불가 설정과 표적 식별·생성 검증·중복 방지·처치·참수·증거·보상 흐름은 보존한다. 추적 확장으로 사냥 표적이 움직이거나 참여자를 추적하지 않는지 검증한다.
  - 일반 자연 생성 좀비에는 적용하지 않는다. 순간이동 대신 정상 이동·길찾기를 사용하며, 멀티플레이 제어권 전환과 경로 요청 빈도 제한을 처리한다.
  - 가림막 뒤 위치 갱신·문/계단·대상 전환·재접속·완료/취소 해제·다수 좀비 부하를 검증한다. 탈출 웨이브까지 운영 코드에 반영했으며 실제 멀티 이동 확인은 남아 있다.

- [x] **계약 금전 보상 3배 → 5배**
  - 원본 대비 보상 배율을 3배에서 5배로 올린다. 현재 정상 3배 보상 대비 약 66.7% 증가다.
  - 새 계약과 기존 미완료 계약·미수락 제안의 금전 보상을 같은 5배 기준으로 맞추고, 화면 표시와 실제 지급액을 일치시킨다. 반복 조회·재시작으로 중복 배율을 적용하지 않는다.
  - 이미 지급한 금액·계좌 잔고·완료/취소 계약·이미 확정된 지급 대기 기록은 소급 변경하지 않는다. 상점 가격·물품 판매 대금·아이템 보상은 이 배율 변경 대상이 아니다.
  - 협동 참여자 지급과 처치 추가 보상을 포함한 계산·이관을 검증한다. 운영 코드에 반영했으며 서버 다음 실행 시 기존 미완료 보상도 이관한다.

- [x] **Metro2033Armory 제거**
  - 기존 Metro 전용 총기·탄창·탄약·부품·제작 도면 등 전용 물품은 보상·환불·교환 없이 삭제한다.
  - 인벤토리·장착품·가방·보관함·차량·바닥과 오프라인 플레이어·미로드 지역을 포함해 정리 방식을 마련한다. 모드를 끈 뒤에도 재접속·지역 로드가 정상인지 검증한다.
  - 정확한 Metro 전용 아이템 ID를 기준으로 제거한다. Metro에서도 사용하는 바닐라·VFE 공용 탄약과 다른 모드 물품은 삭제하지 않는다.
  - 암시장 판매 목록과 이미 생성된 입고 재고·일반 구매 후보 및 저장된 구매안에서 Metro 전용 물품을 제거한다. 무기 묶음 판매 대상에서도 제외한다.
  - 제작 레시피·레시피 해금·임무 보상·보상 전용 품목 등록·전리품 등에서 Metro 전용 참조를 제거한다. 다른 모드의 제작·보상은 유지한다.
  - 서버·클라이언트 모드 목록과 Workshop 목록·의존성 검사·배포 목록도 함께 갱신한다. 기존 삭제 아이템 ID 목록은 미접속 플레이어·미로드 지역 정리에 필요한 동안 유지한다.
  - 배송 대기에 Metro 물품이 남아도 다른 물품 수령을 막지 않도록 처리한다. 혼합 배송의 다른 모드·공용 물품은 보존한다.
  - 관련 코드·설정·판매/보상 카탈로그의 잔여 참조를 검색하고, 모드 제거 상태에서 서버 부팅·클라이언트 접속·암시장·제작·보상·배송이 누락 아이템 오류 없이 동작하는지 검증한다.
  - 5.45×39mm·12.7×108mm·쇠구슬·Hellsing 화살·Ognemet 연료 공급 계획은 폐기한다. 차량용 탄약 3종과 M60 개선 계획은 유지한다.
  - 운영 활성 목록과 자체 정리 코드를 반영했다. 실제 보유품 정리는 다음 접속·지역 로드 시 진행한다.

- [x] **탄약 공급 확대 — 큰 상자 단위 입고**
  - Metro 제거 후 일반 탄약 12종 중 중복 없이 5종을 추첨한다. 선정 시 큰 상자 1~5개를 독립적으로 균등 추첨한다. 서버 전체 공유량이며 구매자마다 같은 수량을 새로 생성하지 않는다.
  - 탄창·상자 크기·수제탄·링크 탄을 별도 탄종으로 추첨하지 않는다. 낱발·상자 포장을 합쳐 실제 탄 수량으로 계산한다.
  - 큰 상자 1개 단위로 구매한다. 기존 큰 상자는 작은 탄약 상자 12개 묶음이다. 앞서 제안한 일반 탄약의 사용자 정의 팩 수량은 아래 큰 상자 기준으로 대체한다.

  | 탄종 | 큰 상자 1개 | 선정 시 총재고 | 평균 |
  |---|---:|---:|---:|
  | .22・9mm・.38・.357・.45 | 각 600발 | 각 600~3,000발 | 각 1,800발 |
  | .44・.223・.30-30・5.56mm・7.62×39mm・7.62×51mm | 각 240발 | 각 240~1,200발 | 각 720발 |
  | 샷건 탄 | 300발 | 300~1,500발 | 900발 |

  - 차량 탄약은 일반 5종 추첨과 분리해 게임 내 매일 입고한다. 차량 일반탄은 12.7×99mm·20×102mm 일반탄 중 1종을 균등 추첨한다. 20×102mm 고폭탄은 25% 확률로 추가 입고한다. 선정된 상품마다 1~5팩을 독립적으로 균등 추첨한다.

  | 차량 탄약 | 1팩 | 선정 시 총재고 |
  |---|---:|---:|
  | 차량용 12.7×99mm | 100발 | 100~500발 |
  | 차량용 20×102mm 일반탄 | 100발 | 100~500발 |
  | 차량용 20×102mm 고폭탄 | 50발 | 50~250발 |

  - 무기 묶음의 초기 탄약과 별개인 보충 판매량이다. 자정 갱신을 사용하며 초기 가격은 상세 기록을 따른다. 코드와 운영 파일 반영 완료. 실제 플레이의 구매·소진 상황을 확인한 뒤 조정한다.

- [x] **무기·탄창·탄약 묶음 판매**
  - 탄창식 총기는 총 1정·호환 탄창 4개·탄창 4개를 채울 분량의 탄약을 함께 판매한다. 탄창은 비워서 지급하고 탄약은 별도로 넣는다.
  - M60은 총 1정·100발 파우치 4개·일반 7.62x51mm 탄약 400발로 구성한다.
  - 추가 탄약·탄창 단품 판매는 유지한다. Metro 총기는 판매 대상에서 제외한다. 내장 탄창식은 장탄수의 2배 실탄을 넣고 묶음 가격은 구성품 기준가를 합산한다.

- [x] **탄창 단품 공급 보장**
  - 운영 중인 탄창식 총기의 호환 탄창을 별도 구매할 수 있도록 한다. 탄약 5종 무작위 추첨에 탄창을 섞지 않으며, 필요한 탄창을 구할 수 있도록 별도 판매 경로를 마련한다.
  - M60 파우치도 포함하고 Metro 전용 탄창은 제외한다. 종류별 하루 8개 공유 재고로 공급하며 가격은 기존 기준가 또는 초기 1,500을 사용한다.

- [x] **구매 전 구성·호환 표시**
  - 결제 전 총기 묶음의 총기명·사용 탄종·호환 탄창명·탄창 개수·총 탄약 수량을 표시한다.
  - 탄창 단품은 호환 총기를, 탄약 상품은 팩/큰 상자당 실제 발수와 구매 수량에 따른 총발수를 표시한다.
  - 표시 내용과 서버가 확정한 결제·배송 구성을 일치시키고 기존 구매 구성품 표시와 연동한다.

- [x] **배송 오류 안내 및 실제 수령 검증**
  - 수령 실패 시 거리·운반 무게·물품 생성 실패 등 확인 가능한 이유를 한국어로 안내하고, 원인을 알 수 없으면 확인되지 않은 이유를 단정하지 않는다.
  - 받은 물품과 아직 남은 주문·미수령 수량을 구분해 표시하고, 실패 주문을 재시도할 수 있음을 안내한다. 부분 수령을 전체 배송 완료로 표시하지 않는다.
  - 실패 주문 뒤의 정상 주문은 계속 처리하며, 재시도·재접속 시 중복 지급되지 않도록 한다. 유료 주문과 배송 진행 기록을 보존한다.
  - 기존 배송 로직 수정은 이미 적용됐다. 이번 예정 작업은 안내 개선과 실제 멀티플레이 우편함 수령·부분 수령·실패 후 재시도 검증이다. 원본 Lua 기반 대역 테스트 결과와 게임 내 검증 결과를 구분해 기록한다.

- [x] **M60 탄약·링크 처리 개선**
  - M60을 일반 7.62x51mm 탄약(`Base.308Bullets`)을 사용하도록 변경하고, 발사 시 빈 링크 배출을 제거한다.
  - 기존 링크 탄(`Base.308BulletsLinked`)은 일반 7.62x51mm 탄약으로 같은 수량만큼 변환한다.
  - 기존 빈 링크(`Base.M60_Link`)와 빈 링크 30개가 든 링크 상자(`Base.M60_Links_Box`)는 제거한다.
  - 플레이어 인벤토리·가방·보관함·차량·바닥을 처리 대상으로 삼는다. 오프라인 플레이어는 다음 접속 시, 미로드 지역은 로드 시 처리한다.
  - 드롭·제작·상자 개봉·발사 경로를 정리해 링크 탄·빈 링크·링크 상자가 다시 생기지 않도록 한다. 기존 100발 링크 결합 레시피도 제거한다.
  - 기존 M60과 탄띠에 장전된 탄은 수량을 보존하면서 새 탄약 방식과 호환되도록 처리한다.
  - 구현 시 반복 접속·지역 재로드에도 변환이 중복되지 않는지, 멀티플레이 장전·발사·탄 소모와 아이템 제거가 정상 동기화되는지 확인한다.
  - 운영 코드 반영 완료. 기존 링크 탄·빈 링크·상자 정리는 다음 접속·지역 로드 시 진행한다.

- [ ] **험비 수리 후 렉·애니메이션 오류**
  - 기존 포즈 변경으로 해결되지 않은 문제다.
  - 적용된 진단 패치로 뒷문 수리 전후 로그를 수집해 오류가 누적되는 객체와 시점을 확인한다.
  - 원인을 확인한 뒤 수정 범위를 정한다. 재접속 없이 수리 후 정상 동작하는지 검증한다.

## 기존 패치의 게임 내 검증

아래 항목은 수정 코드가 이미 적용됐으며, 검증 결과 문제가 남으면 후속 패치를 준비한다.

- [ ] **사냥 임무 표적**: 진행 중인 임무에서 표적 표시, 재접속 후 복구, 참여자 간 동일 표적 확인, 처치·참수·보상까지 확인한다.
- [ ] **방어 임무 생성**: 연속 좀비 생성과 참여자 추적이 실제 멀티플레이에서 정상인지 확인한다.
- [ ] **배송·물품 수령**: 정상 주문 수령, 실패 주문 뒤의 정상 주문 처리, 재시도 시 중복 지급 여부를 확인한다.
- [ ] **Jumbo Tree 제거 후 접속**: 기존 플레이어의 런처 업데이트와 접속을 확인하고, 나무 관련 오류가 다시 발생하면 최신 로그로 별도 조사한다.
