## 개인 출입

설치된 PZLinux의 `client/Context/World/Features/PZLinuxDarkWeb.lua`는 확장 가능한 Lua UI이고, `server/PZLinuxServerCommands.lua`는 서버 요청 처리 경로가 있다. 설치된 게임 JAR에는 `GameServer.sendTeleport(IsoPlayer,float,float,float)`가 존재한다. 바이트코드에서 해당 플레이어 연결에 Teleport 패킷을 보내고 이동 관련 네트워크 상태를 갱신하는 경로를 확인했다.

추가 모드에서 PZLinux 메인 메뉴 입장 요청 → 서버의 컴퓨터 근접/생존/차량 탑승 여부 검증 → 개인 귀환 위치 저장 → 입장 좌표로 이동을 구성한다. 퇴장은 서버가 실제 탈출 지점 근접 여부를 확인하고 저장한 귀환 위치 또는 안전한 대체 지점으로 이동시킨다. 클라이언트가 임의 목적지를 정하게 하지 않는다. 목적지 청크 로딩, 바닥/층, 재접속과 중복 요청은 실제 멀티 검증 대상이다.

## 구역 초기화

### 후속 결정 및 오프라인 인원 판정

사용자 최종 결정: 경과 시간과 무관하게, 서버가 재시작될 때 내부 생존자(로그아웃 캐릭터 포함)가 없으면 초기화한다. 내부 생존자 또는 불확실한 참가 기록이 있으면 보류한다. 72시간 조건과 강제 사망 규칙은 폐기했다.

설치된 게임 JAR의 `zombie.savefile.ServerPlayerDB` 바이트코드에서 `networkPlayers`에 `world`, `steamid`/`username`, `playerIndex`, `x`, `y`, `z`, `isDead`, `data`를 저장하고 읽는 SQL을 확인했다. 따라서 접속자 목록만 볼 필요 없이, 정상 종료 후 해당 월드의 생존 캐릭터 저장 좌표를 도시 경계와 비교해 오프라인 인원을 포함한 잔류 여부를 검사할 수 있다. 계정만으로 합치지 말고 캐릭터 슬롯도 구분한다. 이번 검토는 엔진 저장 코드 확인이며 실제 DB 조회·판정 구현은 하지 않았다.

원정 입퇴장 시 서버에 원정 참여 상태도 기록하고 저장 좌표와 함께 대조하는 방식을 추천한다. 정상 종료와 플레이어 저장 완료 이후, 초기화 전에 판정한다. 기록 불일치·DB 읽기 실패·비정상 종료로 위치를 확신할 수 없는 경우에는 초기화를 보류한다. 내부에서 장기간 로그아웃하면 초기화가 계속 보류되는 정책임을 운영 규칙에 명시해야 한다.

실제 `C:/Users/goods/Zomboid/Saves/Multiplayer/escape_test/`에는 `map/<청크X>/<청크Y>.bin`, `chunkdata/chunkdata_X_Y.bin`, `zpop/zpop_X_Y.bin`, `metagrid/metacell_X_Y.bin`, `apop/` 등이 있다. `players.db`, `vehicles.db`는 별도 전역 DB다. 구형 `map_X_Y.bin`만 지우는 절차를 적용하면 안 된다.

퍼즐의 GameTime modData, 지하 차량 생성의 전역 ModData, 저장 차량, 각종 전역 오브젝트와 동물/지하실 자료도 범위와 관계를 점검해야 한다. 구역 파일 삭제만으로 완전한 초기화가 증명되지는 않는다. 특히 서버가 로드한 청크를 디스크에서 삭제하면 메모리의 내용이 다시 저장될 수 있다.

초기화는 정상 종료 후 재시작 직전에만 수행한다. 내부 생존자가 없다는 판정과 검증된 백업이 필요하며, 운영 중 시간 경과만으로 초기화하거나 입장을 막지 않는다.
