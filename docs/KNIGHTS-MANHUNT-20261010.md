## 2026-10-18 PZLinux 6건 수정

1. 수령 후 비공개 `SyncPendingState`를 전역 호출하던 자체 패치 오류: 원본 상태 필드와 차량 대기 상태를 보존하는 자체 동기화 함수로 교체한다.
2. 지원되지 않는 인자 11개 좀비 생성 호출: 사냥·방어를 포함한 공용 생성 경로를 실제 42.21의 인자 6개 호출로 교체한다. 방어 웨이브는 여러 마리를 한 번에 생성할 수 있도록 사냥 전용 재시도 제한에서 제외한다.
3. 등록되지 않은 사냥 표적 캐시 재사용: 현재 타일 이동 객체·셀 좀비·객체 목록 및 서버 네트워크 ID를 확인하고, 타 계약에 재사용된 객체는 건드리지 않는다.
4. 좌표만으로 일반 좀비를 표적으로 오인: 클라이언트는 계약 태그 또는 해당 계약의 서버 확인 ID로 식별한다. 기억한 객체도 매번 재검사하고 이전 계약 응답 ID를 새 계약에 사용하지 않는다.
5. 잘못된 주문 하나가 전체 배송을 중단: 원본 소포 계획·생성·무게·복구 함수를 사용하되 주문별로 실패를 기록하고 뒤의 정상 주문을 계속 처리한다. 실패한 유료 주문과 부분 배송 상태는 남겨 재시도한다. 자동 삭제·자동 환불은 하지 않는다.
6. 실패한 구버전 주문 이관을 완료 처리: 원본 큐를 영속 배송 장부에 보관하고 모든 항목이 이관된 후에만 완료 표시한다. 이관 진행 기록은 배송 이력이 정리돼도 중복 생성되지 않도록 유지한다. 해석 불가능한 구버전 데이터도 보존한다.

Workshop 파일은 수정하지 않는다. 자체 모드의 작은 진입점 오버레이가 `getModFileReader`로 설치된 원본 소스를 읽어 필요한 비공개 배송 도우미를 연결하고 클라이언트 표적 판정만 교체한다. 원본 이벤트 나머지와 배송 물품 생성·무게 검증은 유지한다. 원본 소스를 배포 ZIP에 복사하지 않으며, PZLinux 업데이트로 연결 지점이 바뀌면 명시적으로 실패하게 해 재검토가 필요함을 알린다.

재현·회귀 검증: `scripts/tests/test-pzlinux-safety.ps1`. 실제 게임 Kahlua와 설치된 원본 Lua를 사용하며 Java 월드·인벤토리 객체는 대역이다. 실제 비공개 함수가 전역에 없는 상태의 수령, 거리 거부, 차량 대기 보존, 반복 수령 중복 방지, 세 배송 출처의 실패 주문 격리, 분할 소포 부분 복구, 무게·동기화 실패 재시도, 두 구버전 큐의 부분 실패/원본 필드 소거/이력 정리 후 재시도, 잘못된 구버전 문자열 보존, 클라이언트 ID·태그·등록 검사 및 실제 원본 이벤트 변환 실행 PASS. 사냥의 잘못된 캐시 복구·중복/사망/타 계약 객체 보존, 방어 3마리 연속 생성도 PASS. 자체 Lua 전체 문법 검사 PASS. 실파일 기반 격리 서버에서 실제 42.21 부팅·`SERVER STARTED`·게임 API 원본 소스 읽기/비공개 도우미 연결·엄격한 클라이언트 코드 변환 컴파일·정상 종료 PASS: `logs/pzlinux-safety-20261018-isolated.log`. 처음 시도한 파일 링크 기반 환경은 리소스 경로 오류로 폐기하고 이전 정상 부팅 환경의 실파일로 검증했다. 실제 플레이어 재접속·임무 표적 표시·수령 조작은 확인 대기다.

## 2026-10-18 표적 미표시 예방 후보 (.2 당시 기록)

진행 중인 `PZLinuxContract-23`은 15:38:39에 `spawn_failed`, 15:38:40에 `method=createZombie onlineId=22732 inWorld=false`를 기록했다. 클라이언트는 같은 위치에서 5초마다 표적을 요청하지만 서버는 같은 ID를 재사용했다. 표적의 클라이언트 수신 실패는 관찰됐으나, `inWorld=false`만으로 월드 미등록을 확정할 수는 없다. 42.21의 `IsoMovingObject.isExistInTheWorld()`는 기본 `square` 필드를 사용하고 `getSquare()`는 `current`를 우선 사용한다.

설치된 42.21 JAR의 실제 공개 시그니처를 확인했다. 원본의 인자 11개 `addZombiesInOutfit` 호출은 존재하지 않으며, 로그에 해당 호출 실패도 있다. 자체 서버 패치 `zzzzzzzz_KnightsDanManhunt.lua`는 사냥 표적 생성만 지원되는 인자 6개 호출로 교체한다. 현재 타일 이동 객체 목록·서버 좀비 목록·셀 객체 목록·유효한 서버 온라인 ID를 모두 확인한 표적만 성공으로 반환한다. 실패를 성공 상태로 숨기는 `createZombie` 대체 경로를 사용하지 않는다. 표적 캐시와 태그가 있는 좀비 목록의 등록을 재검사하고, 잘못된 객체는 제거해 원본 복구 경로가 같은 임무를 다시 시도하도록 한다. 다른 임무에 재사용된 객체와 시체는 삭제하지 않는다. 실패 재시도는 계약별 5초 간격으로 제한한다. 원본 참가자·거리·계약 상태 검사, 참수·증거 생성·보상 경로는 그대로 호출한다.

실제 Kahlua에서 원본 PZLinux의 비공개 ensure 및 공개 restore 경로를 실행하는 `scripts/tests/knights-manhunt.lua` PASS: 지원 시그니처, 잘못된 캐시 복구, 정상 표적 중복 방지, 기본 `square` 검사와 실제 목록 등록의 차이, 재사용된 타 계약 객체 보존, 미등록/온라인 ID 없는 생성 거부, 생성 예외, 실패 재시도 제한, 청크 로드 후 재시도, 사망 상태 재생성 금지. 게임 월드와 Java 좀비는 대역이므로 실제 두 클라이언트 네트워크 수신 검증은 남아 있다. 현재 미표시 문제 전체가 해결됐다고 확정하지 않는다.

당시 후보 릴리스 `0.1.0-20261018.2`는 운영 서버·게임 실행 중이어서 운영 적용하거나 공개하지 않았다. 이후 여섯 문제를 합친 `.3`으로 대체했다. 현재 적용과 검증 범위는 맨 위의 6건 수정 절을 따른다.

## 기존 참수 오류

2026-10-10 사용자가 참수 동작 후 아이템이 없다고 보고했다. 운영 서버 로그는 `PZLinuxContract-11`의 target down 이후 참수 요청마다 `zzz_KnightsDanCoop.lua:201`의 nil 함수 호출 및 `event=decapitate server_exception`을 기록했다. 원본 `PZLinuxContractsFindManhuntRecordForBody`는 local 함수여서 협동 패치에서 전역 호출할 수 없었다. 참수 애니메이션 완료와 서버의 증거 생성 성공은 별개다.

협동 참가자 권한 확인에 필요한 표적 기록 조회를 자체 local 함수로 바꿨다. 원본과 같은 계약 태그 또는 사망 위치 2칸 이내·동일 층·contractId 3·target_down 조건을 사용한다. 이후 원본 WorldEvent가 거리·시체·계약을 검증하고 가방 생성, 시체 제거, 상태 전환을 그대로 수행한다. 표적 소환, 보상 및 완료 방식은 변경하지 않는다.

원본 ISPZLinuxVariablesTables를 실제 Kahlua에서 실행한 협동 테스트에 참수 경로를 추가했다. 비공개 함수가 전역에 없음을 확인하고 태그/사망 위치 기반 비참가자 차단, 등록 참가자 참수 성공, 참수한 사람에게 계약 태그가 붙은 Base.Bag_Mail(Cut target) 및 원본 시체 내용물 생성, 중복 참수 증거 생성 방지 PASS. 기존 협동 지급·은행·주식·ATM 제외 검사도 통과했다. 인벤토리/월드 Java API는 대역이며 실제 멀티 동작은 적용 후 확인한다.

전체 대화 5배속 후보 .4와 합친 `0.1.0-20261010.5`로 배포했다. .4는 단독 배포하지 않고 덮어쓰지 않았다. 서버와 게임 실행 중에는 .3을 유지하다가 사용자의 종료 알림 후 적용했다. 의뢰를 취소하거나 세이브를 수정하지 않았다. 해당 오류는 원본 증거 생성·시체 제거 전에 발생하므로 기존 의뢰와 시체를 유지하고 적용 후 참수를 재시도한다.

`.5` 서명 패키지 생성 완료(65개 자체 파일). PS5.1 설치·복구·같은 버전 재실행·별도 모드 보존 검증 PASS: `research/updater-test-2415c165c30346968fd7cd65c28f1fe8`.
